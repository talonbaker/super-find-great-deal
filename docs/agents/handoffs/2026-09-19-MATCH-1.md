## 1. The knobs

| Knob | Default | Floor | Where it is read |
|---|---|---|---|
| `HideSeekTuning.MatchRounds` | **2** | `MinMatchRounds` = 1, via `MatchRoundsOrFloor` | `HideSeekLoop.CommitTally` (is this a match end) and `EnterHiding` (is this a new match) |
| `HideSeekTuning.MatchTallySec` | **10** | `MinTimerSec` = 1, at the arm | `CommitTally`, in place of `TallySec` (6) when `MatchOver` |

Both follow the record's stated rule: **the floor is applied where the value is READ, never on
construction**, because a struct that clamped in its constructor would need the same floor
re-applied at every `with` expression a test or a tuning panel writes.

`MatchRounds = 2` plus ROUND-1's unconditional role swap at the reset edge is exactly "each player
hides once and seeks once". It is a knob rather than a constant because "best of four" is the same
arithmetic; `MatchRounds = 1` and `= 3` are both tested.

**Why `MatchTallySec` is longer and not the same number.** A round card is one line of arithmetic
both players just watched happen. A match card is the only moment the session ever says who won,
and six seconds is not long enough to read a result, look at the other person and say something
about it.

## 2. What a match is, as rules

- **A match ends when `RoundIndex % MatchRounds == 0`**, evaluated at `CommitTally` on the round
  that just ended (the index advances in the same expression, which is why the card carries its
  own). Round 2 and round 4 end matches; rounds 1 and 3 do not.
- **The winner is decided AFTER the gains are added**, from the same map the totals are copied out
  of, so a name can never disagree with the numbers printed beside it. **0 is a draw**, and 0 is
  also what a card that is not a match end carries — there is no winner to name in the middle of a
  match, and reporting "whoever is ahead" would make one field mean two things.
- **A new match begins at `EnterHiding`, not at the reset edge.** The same Start button runs the
  next round and the next match, so the only thing that can tell them apart is the round index
  about to be played: if it is the first of its match, the scores go to **zero rows** (not an empty
  map — the absolute wire needs a row to carry a zero). Deliberately not at the reset edge, because
  **the holding room is where the result is read** and the totals have to stand there until
  somebody presses Start.
- **`RoundIndex` keeps counting.** Round 3 is match 2's round 1, and the card says both.
- **Roles keep alternating across the boundary, so the player who SOUGHT the last round of a match
  hides the first round of the next.** Nothing in MATCH-1 touches the swap; this is its consequence
  and there is a test pinning it, because it is what a player notices and what a "new match resets
  everything" change would quietly break.
- **A round ended by a disconnect still counts toward its match**, and a match whose last round
  ended that way is over with the totals as they stand. Both gains are zero on such a round, so
  that needs no special case — which is the point.

## 3. The wire

Five fields added to `HideSeekWireTally`, absolute like everything else, and to `Pack`/`Unpack`
and the `ApplyRound` RPC signature:

| Field | Type on the wire | Note |
|---|---|---|
| `MatchOver` | `bool` | the packet's "one byte", carried as a bool to match the neighbouring `EndedByDisconnect` |
| `MatchIndex` | `int` | 1-based; set on **every** card, not only a match end |
| `WinnerPeerId` | `int` | never clamped — identity is not a byte (`HideSeekWire`'s class doc) |
| `HiderTotal` | `byte` | clamped like every other display value |
| `SeekerTotal` | `byte` | " |

**Version.** `HideSeekWire` has **no version constant of its own** and did not grow one. It is
versioned solely by the top-level `NetProfile.ProtocolVersion` (15, set by BASE-1), which this
branch **did not bump** — per the packet's instruction, that is the orchestrator's call at INT-1,
where the wave's total change is visible. Written into `HideSeekWire`'s class doc so the next lane
to widen this message knows which number is the real one.

### Why the totals and the match index are on the card, not derived

The packet's wire paragraph names only `MatchOver` and `WinnerPeerId`; its *tally* paragraph names
the totals and the match index too, and the fold has to reconstruct the server's card exactly or
the two disagree. Beyond that, **the card outlives the numbers it describes** — the argument
`HideSeekTally.RoundIndex` already exists for. **Measured, on the first green smoke run**, at one
sample taken during round 3's Hiding on both peers:

```
RoundA after the third Start: 2 score row(s), all zero; match card still reads 173-171, winner 1196225384
RoundB after the third Start: 2 score row(s), all zero; match card still reads 173-171, winner 1196225384
```

The live map is `0-0` and the card still says who won match 1. HOLD-1's board shows the last card
during the next round (ROUND-1's `EnterHiding` comment is explicit about that), so a board built on
the live map would print `X WON 0–0` from the first Start of every new match onward. The suite now
asserts both halves of that sample.

The first version of the smoke had this bug **in the suite** — it read the live map from the last
sample carrying the card rather than from a sample taken during that card's own Tally, and failed
with `the totals on the wire are level at 0 but the card names peer N the winner`. Caught against
the suite instead of against the game, which is the whole argument in one line.

## 5. Deviations from the packet

1. **The wire carries five new fields, not two.** The packet's wire paragraph says "add `MatchOver`
   and `WinnerPeerId`"; its tally paragraph says the card carries the winner, **both totals** and
   `MatchIndex`. Reconstructing the card from a message missing three of its fields gives a client
   a different card from the server's, and the totals specifically must be frozen — §3 has the
   measurement. Cost: four `int`s and a `bool` on a message sent only when something changes.

2. **`MatchIndex` is set on every card, not only at a match end.** The packet defines it as
   `RoundIndex / MatchRounds`, which is 0 for round 1. `(RoundIndex − 1) / MatchRounds + 1` agrees
   with the packet on every last-round-of-a-match and keeps counting off it, so a board can say
   "MATCH 2 · ROUND 1 OF 2" mid-match. Strict superset of what was asked.

3. **The score reset is keyed on the arithmetic, not on `LastTally.MatchOver`.** Same answer, but
   it cannot be confused by a session whose first card does not exist yet, and a match boundary
   then means the same thing whether the previous round ended at the bin, at the buzzer or on a
   disconnect.

4. **The text functions take a `Func<int,string>? nameOf` and an `in HideSeekTuning`, not just a
   view.** The packet asks for `MatchLine(view)`. A card names the two peers whose roles have
   usually already swapped by the time it is drawn, and names are not on the view; `ROUND 1 OF 2`
   and `found at 1:12` are both questions about the tuning. Both are explicit parameters so the
   copy stays a pure function and `tests/unit` can hold every string.

5. **`found at` is derived, and a timeout says `not found`.** The card records the seek clock the
   seeker had LEFT; the packet's line wants the elapsed time, so it is `SeekingSec − SeekerGained`.
   A seek that timed out gains 0, and the naive arithmetic would print `found at 3:00` — a
   plausible-reading lie about the one instant this game is built around.

6. **`ended: <name> left` keeps its locator** (`ROUND 1 OF 2 · ended: …`, `MATCH 1 · ended: …`)
   rather than replacing the whole line, and **does not suppress the result on the Holding line**.
   The match is over with the totals as they stand; "someone left" tells the survivor nothing they
   do not know while hiding the score still on the board.

7. **Who left is recovered, not stored.** The card knows a role holder went, not which one. Rather
   than a sixth wire field, `MatchLine` reads it off `view.Scores` — the card's hider or seeker
   with no row is the one who is gone — and only when exactly one of the two is missing. The
   standalone functions take an explicit `leaverPeerId` (0 = unknown → "a player").

8. **The smoke's schedule is not the packet's.** The packet suggests
   `start@2,confirm@8,found@20,end@25,start@40,confirm@46,found@58,end@63`. Three changes, all
   forced: a **`lost`** between the rounds (`found` is a LEVEL — a bin holding the target keeps
   holding it — so round 2 would otherwise walk Hiding→Seeking→Together in one tick); **different
   `towers` per round** (equal counts make the match a 175–175 draw and "the winner id equals the
   higher total" vacuous); and a **third `start`** (the score reset is the only observable
   difference between the Start that begins a match and the Start that begins a round). Bot
   lifetime 95 s, derived from the last beat.

9. **`HideSeekDriver` was touched beyond the tally length** — and the tally length is not in the
   driver at all, it is in `CommitTally`. What changed there: the `ApplyRound` RPC signature and
   both send sites (unavoidable — the message widened, which the packet's own two fields already
   required); two log lines, which are the smoke's evidence (`[round] card: …matchOver=…` and
   `[round] match N begins at round M -- scores zeroed: …`); and two read-only accessors `NameOf`
   and `Tuning` that the copy needs. **No logic changed in the driver.**

10. **`scripts/game/BotHarness.cs`'s `RoundTallySample` gained the five card fields.** Outside the
    packet's file list, but nothing in a bot's log could otherwise see a match at all. Additive to
    a private record; the same kind of instrumentation append INT-0 merged from two lanes at once.

11. **`RoundStripWidget` changed after all — one call, no layout.** The packet allows it "only if a
    width change is unavoidable". None was: same one label, same rung, same width policy. The line
    is now `HideSeekText.StripLine(view, self, driver.NameOf, driver.Tuning)`, which is the packet's
    own "the change is in the text function, not the widget" taken literally — the *choice* of
    sentence moved into the text function so CLOCK-1 and HOLD-1 cannot make a different one.

12. **A new test file rather than more of `HideSeekLoopTests.cs`.** `tests/unit/HideSeekMatchTests.cs`,
    to keep the diff additive while DOOR-1, CLOCK-1 and REACH-1 are live on round-adjacent files.
