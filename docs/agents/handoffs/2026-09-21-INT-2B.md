## 7. The rulings

**Ruling 5 — the spawn-pin ORDER.** `ApplySpawnPins` pinned a name the frame it replicated, and
names replicate at different times: PHYS-2 §2.1 measured `SfxProduceBot` teleported onto marker 3
while the still-unnamed witness stood there, 0.6 s at `y = 2.30` on its head, then displaced 5.7 m
from its prop.

**Fixed as the ORDER, and NOT as "reserve the pinned markers from join-order assignment" —
because that is unavailable here by construction.** The search room has exactly four `SearchSpawn`
markers and `Run-MaterialSfxTest` pins names to all four, so there is no unreserved marker to deal
an unnamed joiner instead. What is always available is to let the occupant move first:
`ApplySpawnPins` is two passes now — gather every avatar whose name has not replicated, then pin
only those whose destination is clear of them. A blocked pin is not settled and is asked again next
frame, logged once per peer.

**It cannot deadlock**, and that is why the test is *"has no name yet"* rather than *"is not pinned
yet"*: every named avatar is settled in the pass it is seen, so the waiting set strictly shrinks and
two peers cannot wait on each other.

The geometry is a static on `SpawnPin` so it is asserted in the Godot-free suite (**+4 tests**),
including the one that matters — the 1 m clearance must stay under the 2.1 m marker spacing,
**asserted as a relation** so a later ride that moves the markers gets a red here instead of a
deadlocked suite.

**STALL-1's ruling** — one dated entry added: `Performance.Monitor.TimeProcess` /
`TimePhysicsProcess` are **per-second maxima**, not per-frame values (37 distinct `proc_ms` over
11 055 frames). `PerfHud`'s `frame_ms` and SHELF-1/STOCK-1's `pms` are worst-in-second; like-for-like
comparisons survive, absolutes do not. **HANDS-1's p95 513.820 ms and STOCK-1 §5.6's ~514 ms median
were this stall**, not the hands and not the harness. Plus the ladder row for
