## The fact-source interface — what every other lane implements

```csharp
public interface IRoundFactSource
{
    bool HostPressedStart { get; }      // edge: true for the tick the press happened
    bool HiderHeldRackProp { get; }     // level
    bool HiderPressedConfirm { get; }   // edge
    bool HiderHoldsTarget { get; }      // level
    bool? TargetRetrievable { get; }    // null = this source has not measured it
    bool TargetInDropOff { get; }       // level — a bin does not pulse
    int  TowersCompleted { get; }       // ABSOLUTE, never an increment
    bool AnyPressedEnd { get; }         // edge
    void AfterStep();                   // clear every latched press here
}
```

**How several combine** (`RoundFacts.Combine`, engine-free and unit-tested, deliberately boring):

- **every bool is OR'd** — a source that does not know a fact answers `false` and can never veto
  one that does. That is also what makes the dev script safe to leave in the build: it can add a
  press, never swallow one.
- **`TargetRetrievable` is the first NON-NULL answer**, in registration order. OR-ing would be
  wrong in both directions: `false` is a refusal, `null` is not a yes. All-null ⇒ the loop reads
  it as retrievable, which is the packet's "default true until REACH-1 supplies it".
- **`TowersCompleted` is the MAXIMUM.** It is absolute, so summing double-counts and last-wins
  lets a source that does not know zero a real count.

`AfterStep()` is where an edge dies. Without it one Start press is re-consumed on every tick for
the rest of the session.

## The refusal reasons — every one of these is a sentence BTN-1 has to show

```csharp
public enum HideSeekRefusal : byte
{
    None = 0,
    NeedTwoPlayers        = 1,  // "TWO PLAYERS ARE NEEDED TO START"
    HiderMustHoldAnObject = 2,  // "TAKE SOMETHING OFF THE RACK FIRST"
    PutTheObjectDownFirst = 3,  // "PUT THE OBJECT DOWN FIRST"
    NobodyCouldReachThat  = 4,  // "NOBODY COULD REACH THAT — MOVE IT"
}
```

**There is no branch in the loop that declines to act and returns the state unchanged.** The
reason is set for exactly one tick (it is an answer to a press; a sticky one would still be on
screen two minutes later describing a question nobody remembers asking), rides the wire, is logged
on the server, and is latched for two seconds by the HUD strip. The sentences say what to DO, not
what went wrong — `INTERACTION-BIBLE.md` §5, out of the three playtests the one shipped in-world
control failed.

Values are **stable**: an added reason takes the next number and never renumbers an existing one,
because a stale peer would otherwise render a different sentence than the one the server refused
with.

## The events

```csharp
public event Action<HideSeekPhase, HideSeekPhase>? PhaseChanged;  // (from, to)
public event Action<long>? Found;                                 // the SERVER's found tick
public event Action? ResetRequested;                              // Tally -> Holding
```

All three fire on **every peer**, raised from the applied message, so one server tick produces one
event everywhere. **None fires for a joining peer's first message**: a client that arrives mid-seek
has witnessed nothing, and bursting DOOR-1's door for it would announce a find it missed. It polls
`View` instead — the never-strand rule this repo's flow screens are already built on.

`Found` carries the server's tick, which is why the wire has a `FoundTick` field at all. A driver
raising it with a locally invented number would be lying about the one instant the whole startle
hangs on.

## The dev flag

```
--round-script "<verb>[:<value>]@<seconds>[,...]"      # server only
```

Seconds are measured **from the first player arriving**, not from server boot — see "what the
smoke found" below. Verbs: `start`, `confirm`, `end` (one-tick presses); `found` / `lost` (the
bin, a LEVEL); `object` / `noobject`; `holdtarget` / `droptarget`; `reachable` / `unreachable`;
`towers:N`. Hands default to "holding a rack object, not holding the target, reachability
unmeasured", which is what makes the packet's own four-verb example run a whole round unaided.

**The gate**: it is one `IRoundFactSource` among however many are registered and the driver ORs the
edges, so it is **additive-only** — a human pressing a real Start is never overridden and a real
press is never swallowed. Plus a launch flag nobody types by accident, plus a `[round] DEV` line on
arming and on every fired verb. Nothing here persists a per-player fact, so the trap
`IIntentSource.IsHumanInput` exists for (a bot spending a real achievement into the player's live
profile) cannot be reached from this file.

## What each following lane needs to call

**BTN-1** — implement `IRoundFactSource` on the thing that owns the three buttons, register it with
`HideSeekDriver.Instance.Register(this)`, latch each server-adjudicated press until `AfterStep()`.
The three buttons map to `HostPressedStart`, `HiderPressedConfirm`, `AnyPressedEnd`; the `ObjectRack`
sets `HiderHeldRackProp`; the `DropOffBin` sets `TargetInDropOff` as a **level**, not a pulse — a
bin holding the target keeps holding it, and a one-tick pulse would lose the find to a dropped tick.
Read `HideSeekDriver.Instance.View.Refusal` for the reason to shake and say. `View.Phase` is what
decides which buttons are live (Start only in `Holding`, Confirm only in `Hiding`, End only in
`Together`) — the loop ignores a press in the wrong phase, but a button that lights when it cannot
work is the same defect one level up.

**DOOR-1** — subscribe to `Found` for the burst instant and to `PhaseChanged` for the
`Seeking -> Together` edge. The seeker is already in the vestibule by the time either fires: the
teleport happens on the same server tick as the phase change. The door is round state, not a node
with its own RPC — read `View.Phase == Together` on a late joiner rather than replaying the burst.
`TaskRoom.tscn`'s `WallZPos` is the wall to replace.

**TASK-1** — implement `IRoundFactSource.TowersCompleted` as an **absolute** count of towers
completed *this round*, and zero it on `ResetRequested`. The loop freezes it at the `Found` tick
(`TowersAtFound`), so a source that kept counting across a round boundary shows up as a round that
began with towers already built. Subscribe to `Found` to stop the count and to `PhaseChanged`
(`-> Seeking`) to start it.

**VOICE-1** — `View.Phase`, `View.HiderPeerId` and `View.SeekerPeerId` are the whole room-membership
answer, on every peer, from one message. The mapping is program §2's table: Holding = both in the
holding room; Hiding = hider in search, seeker in holding; Seeking = hider in task, seeker in
search; Together = hider in task, seeker in the vestibule (task-adjacent); Tally = wherever they
were. Prefer deriving the resolver from the phase + role rather than from positions — the positions
are a consequence, and a resolver reading them would disagree with the round for the frame between
the teleport and the next snapshot.

**HOLD-1** — `View.Scores` is a complete `peerId -> cumulative score` map, absolute, present for
every player including at zero, on every peer, from one message. `View.LastTally` is the frozen
card (and carries its own `RoundIndex`, because the live index has already advanced by the time the
card exists). A late joiner is complete from one message: there is no catch-up path to build.

**REACH-1** — answer `TargetRetrievable` with a real `bool` and register **after** any placeholder,
since first-non-null wins. Answering `false` refuses Confirm with `NobodyCouldReachThat` and, at the
Hiding buzzer, buys the hider one 10 s grace before the round is abandoned with the hider scoring 0.

## The reset edge, and the half that is easy to forget

`Gameplay.OnRoundResetRequested` fans both world-state slices:

```csharp
_propManager.ResetForNewPlaythrough();
_reconnects.ResetForNewPlaythrough();
```

BASE-1 named the second one as the thing not to lose, and it is the half that is **invisible when
it breaks**. Props failing to go home shows up on the next frame; a peer that dropped a second
before the edge coming back for up to `ReconnectRegistry.WindowSec` (60 s) at its pre-reset position
holding pre-reset props inside a freshly restored room does not. Clearing is sufficient and simpler
than stamping each ticket with a round index — a reconnector after the edge joins as a fresh peer of
the new round, which is what they are. It runs at the round boundary and nowhere else, so an
ordinary same-round resume is untouched. `tests/unit/RoundFactSourceTests.cs` pins it.

The fan lives in `Gameplay` rather than in the driver because that is where both slices live —
`PropManager` is a child of that node and `ReconnectRegistry` is a plain field on it. A driver
reaching into either would be a round system that knows about prop authority.

## Three things found by measuring rather than by review

**1. A record struct's synthesized equality compares an `ImmutableArray` by REFERENCE.** Two wire
messages encoded one tick apart from identical state compared *unequal*, silently. The driver
decides whether to broadcast by diffing the wire against the last one it sent, so the synthesized
version would have made every sim tick look like a change: **a reliable RPC to every peer at 60 Hz**,
on a stream whose entire design is "absolute values, sent when something moves". Found by a unit
test asserting `Fold(null, w) == Fold(old, w)` that failed while printing two identical-looking
values. `HideSeekWire.Equals` and `HideSeekView.Equals` are hand-written; there is a positive
control test so deleting them goes red. With it, the fastest-moving field is `RemainingTenths`, so
"broadcast on change" self-throttles to ~10 messages a second with no timer anywhere.

**2. A schedule measured from server boot races the clients' own launch.** The first
`--round-script` design counted from the driver's `Setup`, which runs seconds before any Godot
client has finished loading. A `start@8` fires into an empty room, is refused for the only time it
was ever going to fire, and leaves a suite watching a round that never begins. The clock now starts
when the first player arrives. Same failure `.claude/rules/test-suite.md` records under "derive a
bot lifetime from the schedule it must outlive", one level up.

**3. A teleport can be refused and that is not an error.** `RoomTeleport` has an 800 ms per-peer
cooldown, and two phase changes genuinely can fall inside it — a seeker who finds the object within
a second of Confirm would otherwise stand in the search room while the door burst onto an empty
vestibule. Refused moves are queued and retried on the following ticks rather than dropped, and the
first refusal is logged.

## Deviations from the packet

1. **The imported `RoundLoop*` files were DELETED, not left beside the new ones.** The packet says
   "rewrite the phases"; keeping both would leave a second `RoundWire` claiming the same channel and
   a second `RoundPhase` under a name that reads like this game's. Nothing referenced them (checked
   across `**/*.cs`, `**/*.ps1`, `**/*.tscn`). Every lesson in their comments — fold-first ordering,
   the byte-clamp identity bug, the 1 s floor's provenance — was carried into the new files with
   attribution. Cost: `RoundLoopTests.cs`'s 30 tests, replaced by 60.

2. **`RoundIndex` increments at the Tally commit, as the packet's Scores paragraph says**, which
   means the live index reads N+1 while round N's card is on screen. Rather than reinterpret the
   packet, `HideSeekTally` carries its own `RoundIndex`, so the card records the round it is about
   and can never label round 1's result "ROUND 2". If the orchestrator wants the index to move at
   the reset edge instead, it is one line in `EnterHolding`/`CommitTally` and one test.

3. **`TargetRetrievable` is `bool?`, not `bool`.** The packet says "default true", and a plain
   `bool` on a `readonly record struct` defaults to **false** — which would have refused every
   Confirm in the game until REACH-1 landed, on a loop that reads correctly in review. `null` means
   unmeasured and resolves to true.

4. **The fact-source combination lives in `RoundFacts.Combine`, not inside the driver.** The packet
   puts the folding in the driver; that seam is where five independent lanes' answers get
   reconciled, so it was pushed into an engine-free static where xUnit can hold it. The driver calls
   it in one line.

5. **The wire carries `FoundTick`.** Not in the packet's wire list, added because the packet's own
   `Found(tick)` event is otherwise a lie — a driver raising it with the tick it happened to apply
   the message on is not the server's instant, and DOOR-1 needs one instant across two machines.

6. **`NetProfile`'s ladder comment says the next free channel is 22, and 18–20 are left unclaimed.**
   The packet names 21 and the design it came from reserved 21; compacting it down to the ladder's
   stated "next free 18" would move a channel number between a design doc and the code, which is the
   drift that ladder exists to stop. A new test pins the whole ladder against duplicates.

7. **The smoke's room-separation bar excludes the vestibule.** Its first run failed on
   `task <-> vestibule 9.73 m` against a 20 m bar — and that is correct level design, not a defect:
   BASE-1 authored the vestibule as a 3 × 3 m alcove behind the task room's +Z wall, which is the
   whole point of the door DOOR-1 will burst. The three *rooms* keep the 20 m bar (measured 38 / 42
   / 80 m); the vestibule gets a clearance bar against the arrival radius instead.

8. **`UiColumns` gained a rung rather than renaming the cache strip's.** `QuotaStripHeight` is still
   published and still measured by the in-engine layout self-test; quietly aiming an existing rung
   at a different occupant is how a column's arithmetic stops matching what is drawn.

9. **The HUD strip's refusal line could not be asserted by a headless suite.** The packet asks for
   the strip to show a refusal triggered from the dev script "to prove it renders". A `--bot` client
   draws no HUD at all, so the smoke asserts the layer under it — the named refusal reaching the
   server log and both peers' folded views — and the strip's own arithmetic is covered by
   `HideSeekText`'s tests and the column rung test. **A headed capture of the strip with a sentence
   on it is owed**, and it belongs with BTN-1, which is the lane that will make a human produce one.
