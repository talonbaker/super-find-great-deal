### For HOLD-1, which builds its board on this construction

The board is the same object with more rows, and three things are worth copying rather than
re-deciding:

1. **Author the whole panel in one `.tscn` and instance it.** The room files then contain a node
   line and a transform, which is the only form that keeps `SupermarketWorldSelfTest`'s
   packed-vs-live count meaningful — and **add the new prefab to that test's `SectionScenes`
   list**, or its own `_Ready` is invisible to the check (§3).
2. **No colour in the scene file.** `RoundClock.ApplyTokens` is the whole pattern: bind through
   `UiThemeService.Bind`, set the panel's albedo off `tokens.SurfaceSunken` and the two label
   modulates off `tokens.InkRank3` / `InkRank1`. The material carries
   `resource_local_to_scene = true` so three instances are three materials. A panel that loses
   its binding renders white and screams. Add the new file to `UiNoBespokeStylingTests.AlsoScanned`.
3. **Do not give the board a `_Process` and do not give it an `[Export]`.** Register with
   `RoundAudio` (or copy its registry) for the 10 Hz fan-out, and derive anything per-instance
   from the tree rather than from an exported property — §3 is why.

A board is wider than a clock, so `RoundClockLayout.ReferenceChars` does **not** transfer: it is
derived from this panel's 2.4 m width. The method does transfer; the constant is per panel.

## 1. The cue table, with ordinals

`RoundAudioCues.ForEdge` is a pure function of two replicated views. **No new wire, no RPC** —
every peer already receives one absolute message whenever the round moves, so every peer derives
the same list from the same two messages.

| Edge | Cue | `Sfx` | Layer | How it is told apart |
|---|---|---|---|---|
| `Holding → Hiding` | two rising notes, 0.35 s | `ChimeUp` **36** | flat | the phase pair |
| `Hiding`, clock reads 10…1 | 40 ms wood-block click | `Tick` **37** | positional | the floored second changed and lands in 1..10 |
| `Hiding → Hiding`, clock jumps UP | lower, shorter buzz, 0.25 s | `BuzzShort` **40** | flat + positional | the clock only rises once a round: the grace |
| `Hiding → Seeking`, prev clock > 0.15 s | one note, 0.2 s | `Note` **38** | flat | Confirm |
| `Hiding → Seeking`, prev clock ≤ 0.15 s | buzzer, 0.5 s | `RoundBuzz` **39** | flat + positional | the buzzer |
| `Seeking`, clock reads 10…1 | as above | `Tick` **37** | positional | |
| `Seeking → Together` | *nothing* | — | — | DOOR-1 owns the bang |
| `Seeking → Tally` | two blasts | `BuzzDouble` **41** | flat + positional | the seek timed out |
| `Hiding → Tally` | two blasts | `BuzzDouble` **41** | flat + positional | **not in the packet** — §5 |
| `Together → Tally` | the existing sting | `Triumph` **23** | flat | the End press |
| `Tally → Holding` | soft whoosh, 0.4 s | `ResetWhoosh` **42** | flat | the reset edge |
| **any → `Tally` with `EndedByDisconnect`** | *nothing* | — | — | a round that ended because somebody left is not a round that ended |
| **no previous view** | *nothing* | — | — | a late joiner witnessed nothing |

Tick pitch bias is the packet's list exactly: `+0` at 3, `+0.05` at 2, `+0.10` at 1, zero above.
It is a *transposition*, applied through a new `pitchBias` parameter on `SfxLab.PlayUi` /
`PlayStream3D` (additive, defaulted to zero, no existing call site moves) — as distinct from the
`pitchJitter` already there, whose whole job is to be unnoticed.

**Ordinals claimed: 36, 37, 38, 39, 40, 41, 42.** `24–35` are left unused with a one-line comment
naming DOOR-1's `Bang` (24) and SFX-1's material voices (25–35), so all three lanes' enum edits
merge as appends. **Two names differ from the packet's and both are forced:**

- **`RoundBuzz`, not `Buzz`** — `Sfx.Buzz = 17` already exists (the outdoor insect buzz, kept by
  the fork) and an enum cannot carry one name twice.
- **`ResetWhoosh`, not `Whoosh`** — SFX-1 appends a general-purpose `Whoosh` at 35 on its own
  branch for a thrown prop. The orchestrator may collapse the two at merge; nothing but
  `RoundAudioCues` reads this one, so that is a one-line change plus one test constant.

All seven recipes are procedurally synthesised (there are still no audio files in this repo) and
each has a public `…Pcm()` returning raw PCM, the way `GooseHonkPcm` and `TriumphPcm` already do,
so the Godot-free suite asserts the headroom without an audio device. Every number in every
recipe is a named constant — Talon picked none of them and retuning is his.

## 3. What was found by running it, rather than by review

### 3.1 The third payment for one silent engine trap

The clock knew its room through `[Export] public string Room` with `room = "holding"` on each
room's instance line. **It read back as the empty string on every clock**, and all three logged
their node name instead:

```
[clock] 1789857394794 clock RoundClock HOLDING 0:00 shown=-
```

**Godot does not apply a nested PackedScene instance's exported C# script properties on this
project's Godot/Mono build.** This repo has measured it twice before and worked around it twice —
`PropManager.AuthoredKindOf` ("Crate.tscn/Sphere.tscn's authored `kind`/`tint` both silently read
back as the C# field's default for EVERY authored prop") and `Carryable.LoadLiftM`. This is the
third.

**It is quiet because the native properties on the same instance line apply perfectly.** The
clock hangs in exactly the right place, at exactly the right size, not knowing where it is. There
is no error, no warning, and nothing in a diff to see.

Fixed by deriving: `RoundClock.ResolveRoom` walks up until it meets a node named
`SupermarketWorld.HoldingNodeName` / `SearchNodeName` / `TaskNodeName`. A node name **is** native
and survives instancing. The export is deleted rather than left as decoration, and all three room
files plus `RoundClock.tscn` carry a header paragraph saying not to re-add one.

### 3.2 A generalised level check, and the hole it opened — found by planting a fault

`SupermarketWorldSelfTest.CountNodes` stopped at the `Carryable` TYPE (CARRY-1's exception for a
prop's runtime-built outline and shadow). CLOCK-1 needed a second stop, and rather than start a
list the stop was generalised to the **instance boundary**: a node with its own `SceneFilePath`
is authored in that file and is that file's business. That is the rule the PACKED side was
already using — a room's `SceneState` lists an instanced sub-scene as one node and does not
describe its insides — and it subsumes the `Carryable` case exactly.

**Then the plant.** `AddChild(new Node3D())` in `RoundClock._Ready`, which is precisely the defect
`.claude/rules/godot-scenes.md` exists to catch:

```
[supermarket-selftest] SUMMARY failures=0 result=PASS
[supermarket-selftest]   HoldingRoom.tscn   packed=27 live=27
[supermarket-selftest]   SearchRoom.tscn    packed=38 live=38
[supermarket-selftest]   TaskRoom.tscn      packed=44 live=44
```

**Green.** The hole predates this lane — a `Carryable` was stopped at for the same structural
reason — but CLOCK-1 ships the first LEVEL prefab, so it is the first time the hole lets a level
defect through. The fix is the rule applied one level down: `RoundClock.tscn` joins
`SectionScenes` and is checked against its own packed state. The same plant then fails:

```
[supermarket-selftest] FAIL res://scenes/game/world/supermarket/RoundClock.tscn: 4 node(s)
  packed but 5 live. Something is being built in code.
```

Reverted, re-run: `packed=4 live=4`, and every room unchanged. **`Crate.tscn` is deliberately NOT
in that list** — its runtime children are the documented exception CARRY-1 made on purpose.

### 3.3 A capture caught a constant that a green suite could not

`RoundClockLayout.ReferenceChars` (how many characters fit across the panel) was computed from
the textbook "a proportional sans averages 0.55 of its glyph height per advance". Every unit test
passed. The headed capture of the `Together` line showed `3 SORTED` hanging off both ends of the
panel. Measured off that frame — the panel spans 275 px and the eight-character line spans 283 —
**this font's average advance is 0.64 of the glyph height**, so the panel holds 7.8 characters,
not 9. `ReferenceChars` is 7 now and `MinScale` is 0.35 (set by the longest line the wire can
produce, `HID 255 · SEEK 255` at eighteen characters, since both gains are byte-clamped).

The class doc used to claim the estimate errs in the safe direction. It does not — a character
count is an average and is wrong in both directions. That paragraph now says so, and says that
**the render is the instrument**: a change to the panel or the label size owes a new capture, not
just a green suite.

### 3.4 A backtick inside a double-quoted PowerShell string

The first run's failure message printed `its oom export is unset`. The source said
``its `room` export`` — and in a double-quoted PowerShell string a backtick is the escape
character, so `` `r `` became a carriage return. A failure message that mangles itself is one
nobody trusts. Worth a line here because it is invisible until a test fails, which is the one
moment the text matters.

## 5. Deviations from the packet, each with one line of why

1. **`Buzz` → `RoundBuzz`, and `Whoosh` → `ResetWhoosh`.** `Sfx.Buzz = 17` already exists and an
   enum cannot carry a name twice; `Whoosh` is SFX-1's at 35 and two blind lanes must not both
   claim one name.
2. **Ordinals start at 36, not 24.** The orchestrator's cross-lane allocation; 24–35 are left with
   a naming comment so all three enum edits merge as appends.
3. **`ForEdge` takes `HideSeekView?`, not `HideSeekView`.** "A late joiner hears nothing" is the
   single most important property in the cue table and a non-nullable first parameter makes it
   untestable — the caller would have to remember. Now it is an assertion in xUnit and in the
   smoke.
4. **`Hiding → Tally` fires `BuzzDouble`, which is not a row in the packet's table.** That edge is
   the hide that was still broken after the grace. It is the same event as the seek timeout — a
   clock ran out into a tally — and the alternative is the one ending in this game that happens in
   silence.
5. **A round that ends on a disconnect fires nothing**, from any phase. Not in the packet. A
   triumph sting for a player staring at an empty room is the worst of the three, but none of them
   is right, so the rule is on the card rather than on the edge.
6. **`--log-clock` carries the cue sequence too; there is no `--log-sfx` here.** SFX-1 adds that
   flag on its own branch and this branch cannot see it; two lanes inventing one flag name is a
   conflict for no gain. Moving the cue lines under `--log-sfx` after the merge is one line in
   `RoundAudio.Fire`.
7. **`RoundAudio` IS attached on a dedicated server, but only under `--log-clock`,** in a log-only
   mode that plays nothing and drives no clock. The suite needs a server-side reference second and
   putting that inside `HideSeekDriver` would edit ROUND-1's file for a test fixture. The packet's
   "never on a dedicated server" holds for every shipping launch.
8. **The smoke's `--round-script` is not the packet's.** `start@2,confirm@8,found@20,end@25` puts
   Confirm 6 s into a 30 s hide, so the countdown never reaches ten and the packet's own expected
   `Tick×?` is unreachable; `start@2` also races the second bot's connect and would be refused
   `NeedTwoPlayers`. Kept the intervals, moved Confirm to 5 s before the buzzer.
9. **The late joiner is launched on the server's `Hiding -> Seeking` line, not at `t = 12 s`.**
   Same discipline ROUND-1's smoke uses: no wall-clock guess in a fixture.
10. **`Run-RoundClockTest.ps1` cannot cover the `Seeking` tick row.** Seeking is 180 s and no
    suite can count it down; the row is covered in xUnit, and the two phases share one code path
    with the phase passed in, so what the smoke does not reach is the tuning value rather than the
    rule.
11. **The `Seeking` hum is a dial with nothing behind it.** `RoundAudioTuning.HumOn` exists and is
    `false`. The loop pool IS free (`SfxLoop.FireBody` is the only member and nothing in this world
    acquires it), but an `AcquireLoop`/`ReleaseLoop` pair that ships off by default is an
    unexercised path that leaks a pool slot the first time somebody turns it on mid-phase, and the
    pool never steals a loop back. The packet says "implement only if the loop pool is free and say
    so" — it is free, and this is me saying so rather than shipping it.
12. **`SupermarketWorldSelfTest` was edited** (the instance-boundary stop, and `RoundClock.tscn`
    added to `SectionScenes`). Not in the packet's scope; §3.2 is why, and without it the level
    rule is not enforced on this lane's own prefab.
13. **`GameHud.PollIntervalSec` was made public**, and `tests/unit/UiNoBespokeStylingTests.cs`
    gained an `AlsoScanned` list. Both are one-line widenings of an existing guard so the packet's
    "hook into the same cadence" and "the typed-literal test covers the new file" are mechanical
    facts rather than promises.
14. **A fourth capture** (`task-together-sorted.png`) beyond the three asked for — it is the only
    render of the `Together` arm and it is the frame that found §3.3.

Not a deviation, but worth stating: the third HUD row (`INTERCOM: <NAME>`) is VOICE-1's and lives
on its branch. The strip was read for the captures and otherwise untouched.

## 6. The bible check

```

                 on, without hunting for it. The hider is head-down in an aisle during the phase

                 for the round and illegible at the one moment it says what the round was worth.
                 Fixed by RoundClockLayout, and the constant behind it was then corrected off a
                 render (§3.3). (2) A round that ended on a disconnect fired a triumph sting; the
                 card carries EndedByDisconnect precisely so a readout does not have to guess,
                 and both the sound and the words now use it.
```
