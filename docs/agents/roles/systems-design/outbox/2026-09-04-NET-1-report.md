## The ruling on the `Run-BubbleSyncTest` red — **(b), settled, not guessed**

The dispatch asked me to rule between (a) a broken game-side shared counter and (b) an unreliable
harness shape. **It is (b), and the server log settles it rather than suggesting it.**

From `C:\repos\Watis-move1-base\tests\logs\bubble.server.out.log` (the discriminated 2026-09-04
17:26 UTC run, idle machine, clean HEAD):

```
2026-09-04T17:26:47.636Z INFO [server] peer left peer=1681046017 players=2
[bubbletest] reset lever pulled byPeer=1
[bubbletest] reset
```

**Bot C had already disconnected before the reset broadcast was emitted.** The broadcast did not
fail to reach C; it was never addressed to C. No version of (a) is consistent with that ordering.

Cause: C's lifetime is `--duration 26` from **C's own launch** (`Run-BubbleSyncTest.ps1:59`,
`:126-128`); the reset is `--bubble-reset-at 30` from **the server's** launch (`:57`) plus ~4 s of
lever arm/confirm. Two independent clocks, no gate between them, missing by ~100 ms. Byte-identical
across runs because both clocks are deterministic on an idle machine — **a race that always loses
is still a race.**

The counter is positively proven by the same logs: A and B both observed `2 → 0` with empty
`popped`/`hidden` (25 and 27 post-reset samples), C's first sample was
`synced=true count=2 popped=[2,4] hidden=[2,4]`, the client forge appeared as `hidden=[0,2,4]` on
all three peers and moved no tally, and every lever control passed.

**So ECON-1 may copy the shape** — three processes, three logs, observation-keyed assertions,
absence checks with positive controls. **It must not copy one composition rule**: a late joiner's
`--duration` used as an implicit gate for a server-scheduled event. §11.2 states the replacement
property, with the sample count as its own positive control so a closed window fails as *"this
assertion was vacuous"* rather than as *"the broadcast never arrived"*.

**The distinction ECON-1 depends on:** the late-join **dump** (`SendXTo`) is proven. The
late-joiner **broadcast-after-dump** path is **unproven — not disproven** — on today's `main`,
because the only suite with a late joiner exits it before the only such broadcast. That is the
shape of every RPC in §2/§3/§6 and of ECON-1's acceptance criterion 5. It is written into "What
ECON-1 builds first" as a standing warning.

*Fixing the suite is FIX-1's; scope was not widened.*

## Findings worth the orchestrator's attention

1. **`user://` resolves by project NAME, so every worktree on this machine shares ONE profile
   directory.** This is not theoretical — the repo has already been bitten (a suite bot spent
   Talon's first-time "Tough guy" achievement; the fix is recorded at `SandboxAvatar.cs:895-903`).
   A crew save is one order of magnitude worse: hours of play, one file, three concurrent
   worktrees. §7.7 specifies gating on `IIntentSource.IsHumanInput` (the existing precedent) plus
   a `--crew-save-dir` override every suite must pass, and §11.6 adds the absence check with its
   control.
2. **SteamID64 identity is unreachable in the ENet bot suites.** `SteamId64Of` returns 0 off
   Steam (`NetworkManager.cs:462-463`) and `Gameplay.cs:961-965` already records that the resumed
   branch "can never actually" fire in CI. §11's assertion 6 is therefore unprovable as the packet
   worded it. §11.5 gives three arms, recommends proving it at the pure-logic layer (the repo's
   own existing answer to this exact wall), and surfaces the alternative — a test-only stable ENet
   identity — as a fork, because it touches the auth boundary and rate limiter.
3. **§8 spends the last spare snapshot bit.** `flags2` bit 7 is documented as the one remaining
   spare (`NetCodec.cs:126-132`). Using it for `RadioTransmitting` costs zero bytes and satisfies
   `VoiceManager.cs:80-89`'s hard contract that PA resolve identically on both sides from
   replicated state. The alternative (a reliable RPC on a new channel with its own dump and
   `Synced` bool) is written out rather than dismissed. After v15, both snapshot flags bytes are
   full and the next flag is a length change.
4. **The encumbrance ceiling is real and the design must know it.** `max(0.55, 1/(1+kg×0.055))`
   reaches its floor at **~14.9 kg**; past that, extra mass costs a rider nothing. "Heavy" as a
   speed lever is bounded, and anything past it is a capability denial — which is what
   MECHANICS-BIBLE §8.3's research default already recommends. In Open questions.
5. **The dispatcher is cheaper than expected and still out.** No media path exists anywhere
   (`grep VideoStream|VideoPlayer|CameraFeed scripts/` → nothing). But the cheapest future shape
   needs **no new wire at all**: remote avatars are already replicated, `--spectate-cam` already
   attaches a follow camera, and `SandboxAvatar.cs:833` says outright that the seam "is what a
   future spectate mode will use". Dispatcher = a target-picker UI + the shipped rig + §8's radio.
6. **`$200 → $400 → $800 → $1600` is a two-line `.tres` edit and nothing else.**
   `EarlyRoundsDemand = PackedInt32Array(200)`, `TailGrowthFactor = 2.0`, verified against
   `QuotaMath.Demand`'s strict-increase rule (`QuotaMath.cs:39-55`). `QuotaLedger.ServerBank`'s
   declared-but-uncalled slot (`:166`) is exactly the delivery handler's hook, and its band-live
   guard already resolves the delivery-races-the-verdict case for free.
7. **Two channels, not one.** Crew takes 17, packages take 18, and the ladder's "next free is 17"
   comment must move to 19 **in the same commit** — the ladder itself records that two branches
   both claiming a number is invisible until a playtest (`NetProfile.cs:170-174`).

## Corrections to the packet

1. **The `Run-BubbleSyncTest` ruling is (b), and the evidence settles it.** The coordinator's
   mid-task note said the fork was "genuinely open on this evidence" and should not be picked. It
   is not open: the server log shows C had left before the broadcast was emitted, and a broadcast
   never addressed to a peer cannot indict the broadcast path. One detail in that note is also
   slightly off — C's shorter sample count is not "a later join and a common exit wall-clock";
   `$WitnessDurationSec` is 36 and `$LateDurationSec` is 26 (`:58-59`), so C exits **ten seconds
   earlier** by construction, and the reset falls in that gap. The distinction matters because it
   makes the fix a one-line gate rather than a timing hunt.
2. **"FAILS 3/3" resolved as 3 runs of 3, not 3 failures.** The measured run produces exactly
   **one** failure. Recorded so nobody hunts for two more.
3. **Six of the dispatch's file:line cites had drifted by one to five lines** (and
   `PropManager.cs` lives under `scripts/game/props/`, plural). All six are tabled at the head of
   §1 with the corrected values and used in corrected form throughout. The rest verified exactly.
4. **§11's assertion 6 cannot be written as the packet worded it** (finding 2 above). Not a
   defect in the packet's intent — the wall is a property of the ENet transport — but the
   assertion needs the §11.5 treatment or it will pass vacuously.
5. **§2's fork phrasing invites a strawman and I did not take it.** "One node per value" would
   have grown the late-join funnel by four. The recommendation is one node per *system*
   (`QuotaLedger` unchanged + one new `CrewState`), and the cycle index is not stored at all
   because `CycleDriver.CyclesElapsed` is already replicated and already dumped.
