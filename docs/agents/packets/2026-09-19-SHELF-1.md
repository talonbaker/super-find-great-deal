## Goal

The search room becomes a place you have to root through. The brief: small, boxy, no architectural
detail — the visual draw is the density of items covering every surface. Shape theme: everything is
a red cube except the one thing that is not.

## Build (all authored in `SearchRoom.tscn` and sub-scenes; nothing built in code)

- **Four aisles** of shelving: each a static frame (uprights + 3 shelves, `BoxShape3D`s), 0.5 m
  deep, 1.8 m tall, running the room's length, with a walkable gap of 1.6 m between aisles and
  around the edge. Two **end-caps** and **six floor bins** (open-top boxes, static walls, big enough
  to hide a cube under when tipped — bins are `RigidBody3D` `NetworkedProp`s so they can be tipped
  and carried; mass 6 kg).
- **Products, not red cubes** (amended 2026-09-19 by the orchestrator; spec
  `C:/repos/PROPOSAL-2026-09-19-SOUND-STATES.md` §2): three prop prefabs from SFX-1 —
  `Can.tscn`, `CerealBox.tscn`, `Produce.tscn`, each carrying its own material voice — instanced
  ~120 times in total, grouped by kind per aisle the way a supermarket shelves them (cans on one
  aisle, boxes on another, produce in the bins and end-caps), deterministic node names
  (`Can_000` …, `Box_000` …, `Produce_000` …) so `AdoptAuthoredProps`' path sort is stable. All
  `NetworkedProp` + `Interactable`. A product pushed off a shelf falls, rolls, can be picked up.
  Measure and report: adopt time, server frame time p50/p95 at rest, and with two bots knocking
  everything off (`--carry-script` / a scripted shove), the loose-stream bandwidth, and
  `PeakLive3DVoices` / `OneShotSteals` during the shove. If 120 is too heavy for a 60 Hz server sim
  on this machine, find the count that holds p95 under 8 ms and report both numbers — the number
  is Talon's to trade.
- **Near-miss objects**: the rack's three are one of each kind wearing a gold "great deal" band
  (`DealCan.tscn`, `DealBox.tscn`, `DealProduce.tscn` — same size class, same material voice, one
  gold ring/stripe mesh added; BTN-1 authors the rack in the holding room, you author the three
  scenes and hand them over). The hider's choice of object is the choice of which population it
  hides in; the seeker tells a deal item from its neighbours only by the band.
- **`RoomBounds`** `Area3D` for the search room (CARRY-1 expects it; verify it encloses every shelf
  top and the bins; nothing authored outside it).
- Materials: one flat `StandardMaterial3D` per product kind (silver-grey cans, one box colour, orange
  produce), shelves a different grey than the walls so aisles read in a capture. No textures, no
  models.
- **Owed suite**: `tests/Run-AuthoredPropTest.ps1` back — every authored prop in the room is
  adopted with a stable id on both a server and a late-joining bot, ids identical across peers.
