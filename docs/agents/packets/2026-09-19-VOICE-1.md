## What exists

`scripts/voice/VoiceManager.cs` — `PaResolver : Func<int,bool>` evaluated per talker each frame;
`VoiceSpeaker.SetRoute(VoiceRoute.Pa)` = no falloff + the PA bus (`EnsurePaBusName()`: overdrive →
2.2 kHz lowpass → boxy reverb). `scripts/net/VoiceProximityGate.cs` — the server-side relay cull
reads the **same** resolver; the hazard is written in its header: a gate that does not know who is
on PA silently mutes the intercom. It logs `paResolver=wired|NOT-WIRED` on first gated relay.
`VoiceManager.GetEmitRouting()` returns the routing verdict as JSON — the suites assert on it.
`--voice-send/--voice-flood/--voice-pa-all` test flags; `Run-VoiceTest.ps1`, `Run-VoiceGateTest.ps1`.

## Build

1. Resolver predicate: on each **client**, talker T is on `Pa` iff `RoomOf(T) != RoomOf(local)`;
   otherwise `Proximity`. The listener-relative decision is per client, which the existing
   per-client `SetRoute` already supports.
2. On the **server**, the gate's exemption: relay T → L always when `RoomOf(T) != RoomOf(L)`
   (PA) — i.e. never cull cross-room; keep the distance cull for same-room pairs (harmless in a
   10 m room, but leave the mechanism on so the suite still exercises it). Confirm the log line reads
   `paResolver=wired`.
3. Room membership: from ROUND-1's authoritative teleports (the driver knows where it put everyone),
   not from position sampling — a player standing in a doorway must not flap between routes. Expose
   `RoomOf(peerId)` on the round wire if ROUND-1 did not already.
4. The intercom "character": keep the three-effect bus as is; add one knob `IntercomWetDb` so Talon
   can pull it back if it is too muddy for taunting. Speaking on PA also drives a small lamp on the
   HUD strip ("INTERCOM: <name>") so a hider knows the seeker is talking even at low volume.
5. No mute-by-phase, no push-to-talk changes. Voice is always on.
