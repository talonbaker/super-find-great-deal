## Goal

The server runs the round; every peer knows the phase, the timer, the roles and the scores from one
absolute message; players are moved between rooms on phase transitions; a thin HUD strip shows phase,
timer and role. Buttons, the bin, the door and the towers are other lanes — this packet exposes the
**facts** they fold in and the **events** they consume.

## Build

### 1. `scripts/game/round/HideSeekLoop.cs` (+ state, input, tuning, wire) — engine-free

Rewrite the phases as `HideSeekPhase { Holding, Hiding, Seeking, Together, Tally }`. Keep the shape:
one `Step`, facts folded first, transition evaluated second, one-tick edges.

Input facts (all absolute, all from other lanes or the driver):
`HumanPeerIds` (ordered by join), `HostPressedStart`, `HiderHeldRackProp` (bool), `HiderPressedConfirm`,
`HiderHoldsTarget` (bool), `TargetRetrievable` (bool, default true; REACH-1 supplies the real value —
program doc §5b), `TargetInDropOff` (bool), `TowersCompleted` (int), `AnyPressedEnd`.

Tuning: `HidingSec 30`, `SeekingSec 180`, `TallySec 6`, `MinTimerSec 1`.

Transitions (each refusal is a **named reason** the button lane can show; a silent no-op is a defect):
- Holding → Hiding: `HostPressedStart` and exactly two humans (`NeedTwoPlayers`) and
  `HiderHeldRackProp` (`HiderMustHoldAnObject`).
- Hiding → Seeking: `HiderPressedConfirm` and not `HiderHoldsTarget` (`PutTheObjectDownFirst`) and
  `TargetRetrievable` (`NobodyCouldReachThat`). On **timer expiry** with the target not retrievable
  (still held, or failing the check), the loop does not start Seeking on a broken hide: it extends
  Hiding by `HidingGraceSec` (10 s, once) and broadcasts the reason; if still not retrievable after
  the grace, the round goes to Tally with hider score 0 for the round (the hide failed, the seeker
  cannot be asked to find it).
- Seeking → Together: `TargetInDropOff` (sets `FoundTick`, freezes `TowersAtFound`); timer expiry →
  Tally directly with `TowersAtFound = TowersCompleted` and seeker score 0.
- Together → Tally: `AnyPressedEnd`.
- Tally → Holding after `TallySec`; `ResetRequested` true for exactly that tick; roles swap.

Roles: `HiderPeerId`, `SeekerPeerId`; first round hider = first joined human (the host), then swap
each Tally. If a role holder disconnects mid-round → Tally immediately with the other's score kept,
then Holding.

Scores: `Scores : ImmutableDictionary<int,int>` cumulative per peer; `LastTally` computed once at the
Together/Seeking → Tally commit: hider += `TowersAtFound`, seeker += `RemainingSec` at the find
(0 on timeout). `RoundIndex` increments at the commit.

Wire: absolute values only (`Fold(null, wire) == Fold(old, wire)`), identities `int`, scores clamped
to a sane range, `RoundChannel = 21` reserved in `NetProfile`. One `[Rpc(Authority, Reliable)]` from
the driver on every change and on late-join dump.

### 2. `HideSeekDriver` (Node, server-side, in `Gameplay`)

Steps the loop at the sim tick, folds facts from providers other lanes register (`IRoundFactSource`
with a default that returns false/0 so this packet runs standalone), broadcasts the wire, and on each
phase transition **teleports** the affected peers to the named spawn points via the epoch-bump
teleport: Hiding → hider to `search`; Seeking → hider to `task`, seeker to `search`; Together →
seeker to `vestibule`; Holding → everyone to `holding`. Emits C# events for other lanes:
`PhaseChanged(from, to)`, `Found(tick)`, `ResetRequested()`.

Dev input so this packet can be driven without buttons: `--round-script "start@2,confirm@8,found@20,end@25"`
(seconds) that feeds the facts from a bot or the host — clearly a dev flag, removed by nobody, gated
off for humans.

### 3. HUD strip

Top-centre: phase name, `mm:ss` timer, your role ("YOU HIDE" / "YOU SEEK"), round index. Built from
`UiRecipes`; passes the existing UI law tests. Shows the refusal reason for two seconds when the driver
broadcasts one (BTN-1 will trigger these; you trigger them from the dev script to prove it renders).
