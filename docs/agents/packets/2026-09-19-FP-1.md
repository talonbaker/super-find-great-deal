## Goal

The local human plays in first person. Mouse look drives yaw and pitch; WASD moves relative to the
look yaw; the camera sits at the avatar's eye height; the local player's own body is not drawn; the
existing third-person rig is no longer attached for humans. Bots, the server sim, prediction and
reconciliation are untouched. This is a deliberate break from all prior third-person work — do not
keep a toggle back to the orbit camera.

## What exists (read before writing)

- `scripts/net/AvatarMotor.cs` — `Step(state, intent, speedFactor, dt)` is camera-agnostic; its only
  camera reference is `SanitizeAimPitch` clamping to `SandboxCamera.PitchMin/PitchMax`.
- `scripts/game/sandbox/MoveIntent.cs` — `MoveDir` is **already world space**; `AimYaw`/`AimPitch`
  are the look angles the server uses to reconstruct the aim ray. `IIntentSource` is the seam.
- `LocalInputIntentSource` (in `IntentSources.cs`) is the one place the camera meets the motor: it
  turns WASD into world space using the camera yaw. Write a sibling, do not fork the motor.
- `AvatarProportions.EyeHeightM` / `AimAnchorLocal` — the eye mount. Voice already emits from it
  (`SandboxAvatar.VoiceOriginGlobalPosition`).
- `SandboxCamera.cs` (third-person, ~1000 lines) — `Attach/Reattach/Detach` are the only writers of
  `SandboxAvatar._followCamera`. Read its mouse handling (`_UnhandledInput`, `MouseSensitivity`,
  `PitchMin/PitchMax`) and its capture/release of the mouse cursor on pause.
- `AvatarMotor` yaws the body toward **movement** direction and that yaw is replicated and checked in
  reconciliation (`YawEpsilonRad`). Decide and document: in first person the body yaw follows the
  look yaw (preferred — other players should see which way you are facing), and the change must keep
  `PredictionMatchTests` green. If the motor needs a "yaw follows aim" mode, add it as a `MotorTuning`
  knob defaulting on for this game, not as a code fork.

## Build

1. `scripts/game/sandbox/FirstPersonCamera.cs` — a `Node3D` child of the avatar at `AimAnchorLocal`
   holding a `Camera3D`. Exposes `Yaw`, `Pitch` (radians, same convention as `SandboxCamera.Yaw` so
   `MoveIntent.AimYaw` needs no conversion). Mouse look in `_UnhandledInput` with the same sensitivity
   knob and pitch clamp; cursor captured while playing, released by the pause overlay exactly as today.
   Defaults tuned against motion sickness: vertical FOV 75°, **no head bob, no camera lag, no
   speed-FOV**, near plane 0.05 m. A gamepad right-stick path is not required.
2. `FirstPersonIntentSource : IIntentSource` — WASD relative to `Yaw`, `AimYaw/AimPitch` from the
   camera, jump/sprint/interact/throw as today. `IsHumanInput = true`.
3. Attach it where `SandboxCamera` is attached for the locally-controlled human today
   (`SandboxAvatar.ConfigureNetworkedInstance`) and set `AimCamera` to the new `Camera3D` so
   `InteractTargeting` keeps working. Remove the third-person attach for humans. Leave `SandboxCamera`
   in the tree only if a tool (`--spectate-cam`, captures) still needs it; say which in the handoff.
4. Hide the local player's own body: the `AvatarVisual` mesh(es) get a `VisualInstance3D.Layers` mask
   the first-person camera does not render (cull mask), so other players and the spectate camera still
   see the body and its nameplate. Do not delete the visual, do not scale it to zero.
5. The nameplate of the local player is not drawn to itself (it already isn't — verify).
