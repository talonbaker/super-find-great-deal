## Goal

One authoritative countdown, seen two ways at once: the HUD strip (exists) and a physical clock on
the wall of every room. The clock is also where the round is heard: ticks in the last seconds, the
buzzer, the chime on Start, the sting on the tally. A hider head-down in an aisle feels the time.

## Build

### `RoundClock` (authored once as `scenes/game/world/supermarket/RoundClock.tscn`, instanced in
`HoldingRoom.tscn`, `SearchRoom.tscn`, `TaskRoom.tscn`, high on a wall facing the room's centre)

- A dark panel mesh with two `Label3D`s, unshaded, `no_depth_test` off, billboard off, sized so
  `M:SS` reads from 8 m in first person (FOV 75): line 1 the phase word (`HideSeekText.PhaseName`),
  line 2 the timer (`HideSeekText.TimerText`, floors, never rounds up — reuse, do not reimplement).
  In `Together` and `Tally` line 2 shows the tally line (`HideSeekText` gets a `ClockLine` next to
  `StripLine`; both engine-free, both unit-tested).
- Client-side reader of `HideSeekDriver.Instance.View`, polled at 10 Hz like the HUD (hook into the
  same cadence, do not add a per-frame `_Process`). Hidden until `Synced`. **No new wire, no RPC.**
  A late joiner's clock is right from the first message (assert it in the smoke).
- Panel and digit colours through the UI design tokens (`UiTokens`) so the clock and the HUD strip
  cannot disagree in colour; the unit test that scans for typed literals covers the new file.

### `RoundAudio` (one per client, under the HUD root or the world; never on a dedicated server)

- Engine-free `RoundAudioCues.ForEdge(HideSeekView previous, HideSeekView next) → IReadOnlyList<RoundCue>`
  where `RoundCue { Sound, Flat, Positional, PitchBias }`. Cases:

| Edge | Cue | Layer |
|---|---|---|
| `Holding → Hiding` | `ChimeUp` (two rising notes, 0.35 s) | flat |
| `Hiding`, remaining crosses 10, 9, … 1 | `Tick` (40 ms wood-block click); pitch bias +0/+0.05/+0.1 for 3, 2, 1 | positional from every clock |
| `Hiding` remaining hits 0 and phase stays `Hiding` (grace) | `BuzzShort` (lower, 0.25 s) | positional + flat |
| `Hiding → Seeking` via Confirm | `Note` (one note, 0.2 s) | flat |
| `Hiding → Seeking` via buzzer | `Buzz` (0.5 s) | positional + flat |
| `Seeking`, remaining crosses 10 … 1 | `Tick` as above | positional |
| `Seeking → Tally` (timeout) | `BuzzDouble` | positional + flat |
| `Seeking → Together` (Found) | nothing — DOOR-1 owns the bang | — |
| `Together → Tally` | existing `Triumph` | flat |
| `Tally → Holding` (reset) | `Whoosh` (existing if SFX-1 landed; else add it here, same name, same ordinal — coordinate through the orchestrator) | flat |

- New `Sfx` recipes appended (ordinal contract): `ChimeUp, Tick, Note, Buzz, BuzzShort, BuzzDouble`.
  Flat cues via `SfxLab.PlayUi`; positional cues via `PlayStream3D` at each `RoundClock`'s position
  (the clocks register with `RoundAudio` on `_Ready`). The phase hum from the proposal is optional:
  a `SfxLoop.SearchHum` on the clocks during `Seeking`, default **off** (`RoundAudioTuning.HumOn`);
  implement only if the loop pool is free and say so.
- `Tick` uses the client's view, so on a 10 Hz wire it fires within 100 ms of the true second; that
  is fine. Do not extrapolate.
