## Goal

A player picks an object up by hand, carries it with weight, turns it, sets it down exactly where
they are holding it, or throws it — and every other peer sees the same thing. The hider needs this to
hide an object under a bin; the seeker needs it to root through shelves; the task room needs it to
stack. Direct physics interaction, no menus, no context prompts.

## What exists (read all of it before writing)

- **Authority layer** — `scripts/game/props/PropManager.cs` (~1000 lines) and `NetworkedProp.cs`.
  Client `ClientRequestGrab/Drop/Throw` → server validates (range, one-per-peer, first-grab-wins) →
  `ApplyPropState` (reliable, CallLocal) is the **single funnel** on every peer. Held = transform
  derived from the holder's anchor, nothing streamed. Loose = server simulates, streams unreliable
  on the prop channel. Resting = latched. Late-join dump, disconnect release, reconnect restore,
  `GrabDenial` reasons (a silent refusal is a defect class). **Keep all of this.**
- **Feel layer** — `scripts/game/sandbox/feel/`: `Interactor` (the hand: candidate Area3D, aim cone
  with hysteresis, line-of-sight, critically-damped spring `Spring(ref pos, ref vel, anchor, omega, dt)`
  driving a frozen kinematic body, heft dials, swing, droop, lean, squash, throw inheriting the item's
  velocity), `Interactable` (component on a RigidBody3D), `InteractionSlot` (the place verb: cylinder
  reach, tag, `Verdict`), `FeelSelfTest` + `tests/Run-FeelTest.ps1`. **Entirely local.** It was built
  after Talon's note that the old carry never looked held; keep its feel.
- `CarryController`/`Carryable` — the older kinematic carry the authority layer wraps today.
- `InteractTargeting.Pick` — the one rule for what E acts on. `IPressable` / `InteractHighlighter`.
- `SandboxAvatar.HandleCarryIntent` — the one funnel for the interact press (pressable → world →
  drop → grab). `MoveIntent.AimYaw/AimPitch` is the aim ray (FP-1 is in flight; do not depend on its
  camera node — derive the ray from the intent so bots and the server agree).

## Build

1. **Holder-side visual = the feel spring.** When `ApplyPropState` says *I* hold prop P, bind
   `Interactor` to P's body (or port `Interactor`'s carry update into `NetworkedProp.BindToHolder`
   for the local holder — pick the one that leaves `feel/` intact and say why). The spring seeds at
   the item, not the hand (the documented anti-pop). Other peers keep deriving P's transform from the
   holder's anchor as today; the visual mismatch is the spring lag and is acceptable.
2. **Rotate held.** Hold a modifier (default: right mouse button) and mouse-move / scroll to yaw and
   pitch the held basis; the basis is local to the holder until release. A new `MoveIntent` field is
   **not** needed — the release transform carries it.
3. **Place.** `ClientRequestPlace(propId, Transform3D intended)`: the server validates range (the
   same slack rule as grab), that the sender holds it, and that the intended position is within
   `PlaceReachM` of the holder's hand; then runs **placement integrity layer 1** (program doc §5b —
   read it, it is a ruling from Talon): (a) the prop's collision shape at the intended transform is
   inside the room's authored bounds volume (an `Area3D` named `RoomBounds` in each room section —
   add one to each of BASE-1's three rooms); (b) a shape overlap query against static geometry and
   every other prop (excluding itself and the holder) reports penetration depth ≤
   `PlaceOverlapToleranceM` (default 0.02). Pass → release into Loose with zero velocity at the
   intended transform so it settles and latches Resting; the prop's **`LastGoodTransform`** is set to
   the intended transform. Fail → refuse with the reason `DoesNotFitThere` (a `GrabDenial`-style
   enum: shake + dull click + the reason text on the presser; silence is a defect). The prop stays in
   hand. `LastGoodTransform` is also set on every Resting latch **only if** the same two tests pass
   at the rest transform (REACH-1 adds the correction path; you only record). Expose the two tests
   as one engine-facing method `PlacementIntegrity.Check(propBody, transform) → Verdict` so REACH-1
   calls the same code. Slots (`InteractionSlot`) participate only when the server knows the slot:
   expose an `IPlacementValidator` hook with the default "free placement"; TASK-1 registers pads.
4. **Throw** stays the existing path; the throw inherits the spring velocity on the holder
   (`ThrowScale`), and the server uses the intent's aim ray + a fixed speed — document the mismatch.
5. Bindings: E grab/place (place when holding and aiming at a surface within reach; drop-in-place
   otherwise), Q throw, RMB+mouse rotate. Live glyphs via `ControlGlyphs`.
6. Every prop stays a `RigidBody3D` with `Interactable` **and** `NetworkedProp`; authored in `.tscn`;
   `PropManager.AdoptAuthoredProps` unchanged. Nested-scene `[Export]` values read back as defaults on
   this Mono build — do not gate behaviour on them (see `PropManager.AuthoredKindOf`).
